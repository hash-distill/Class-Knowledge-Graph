# Contributing

See the [README](README.md) for environments and entry points. The application, media inference, and vision training use separate dependency environments; starting the workbench does not require installing every model dependency.

Preserve the `/api/review` contract, error structure, and media Range/HEAD behavior when changing the API. Run heavy jobs through the persistent queue or separate scripts. Keep teacher edits, manual reviews, derived scores, and original recognition artifacts separate.

For vision or scoring changes, document label provenance, valid support, unknown intervals, and method versions. A new geometric rule must not be labeled model recognition or human ground truth. Split samples by classroom or recording. Report unit checks, fixed-crop metrics, and independent classroom results separately.

Before submitting, run backend tests, `npm test`, `npm run build`, and `python scripts/prepare_release.py --check`. State whether checks requiring real models, a remote server, or an installer were actually run. Use clearly synthetic test fixtures. Do not commit real student images, speech, teacher records, private configuration, or credentials.

The interface defaults to English. Preserve the source language of lesson content and evidence quotations. Translate interface text and illustrative documentation examples without rewriting original classroom evidence.

The unified release tree is generated by `scripts/prepare_release.py` and excludes nested module `.git` directories. Do not reset existing module repositories or upload them as undeclared submodules.
